Both sor and cleaned are rebuilt in a staging schema and swapped in with one transaction, so the API never sees half-loaded data. The removal ledger survives every rebuild and is re-applied by the transform, so a removed person can't come back with a refresh. Dashed lines are reads, not data flowing through our pipeline: the transform reads the ledger, and the browser loads each photo straight from DPS.
